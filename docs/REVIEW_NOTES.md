# Разбор замечаний преподавателя

## Принятые решения

1. **«numeric std logic заменить на logic unsigned».** Пользователь уточнил точное имя: `IEEE.STD_LOGIC_UNSIGNED`. Оно используется для беззнаковых сравнений веса; `NUMERIC_STD` отсутствует во всех исходниках и тестбенчах. Счётчики остаются ограниченными `natural`: это синтезируемые аппаратные счётчики с необходимым числом разрядов, а не 32-разрядные регистры по умолчанию.
2. **Счётчики вниз до нуля.** Отбраковка загружает N−1 при входе в REJECT_STATE, затем уменьшает значение до нуля. Состояние активно ровно N тактов, включая N=1. Делитель шага считает STEP_CYCLES−1 … 0, позиция — 15 … 0. Логическая позиция профиля равна 15−position_r.
3. **«D-заглушки».** Термин неоднозначен: это могут быть промежуточные `_d`/`nextState` либо присваивания по умолчанию перед основной цепочкой условий. В реализации нет ни тех, ни других. В тактовом процессе отсутствие присваивания означает сохранение регистра; отдельная заглушка для этого не нужна.
4. **Противоречие про `process(all)`.** Фразы «убрать» и «перенести if в process all» несовместимы. Принята явно сформулированная версия «только процессы по такту»: все процессы синтезируемого кода имеют такт и асинхронный сброс. Проверки `if` веса генератора выполняются на фронте при нулевом счётчике шага. Постоянный выход конвейера и декодирование состояния отбраковки заданы прямыми конкурентными присваиваниями без дополнительной задержки.
5. **Убрать `weight = 0`.** Убрано предварительное обнуление перед цепочкой `if`. Сохранены сброс и явная ветвь `else` для пустых позиций. Полностью убрать ноль из тактового процесса означало бы удерживать вес прошлого изделия; в комбинационном неполном процессе это могло бы привести к защёлке. Ноль здесь — реальное входное воздействие, а не don't-care. Никаких значений `'-'` для синтеза не вводилось.
6. **«Функцию с весом перенести».** В текущей версии пользовательской функции нет: вероятнее всего, речь о комбинационной цепочке формирования `weight_o`. Именно она перенесена в тактовый процесс. Декодируется входящая позиция, чтобы регистрация выходов не добавляла лишний такт к профилю.

`STD_LOGIC_UNSIGNED` — исторический пакет Synopsys, а не стандартный IEEE-пакет, несмотря на имя библиотеки. Выбор сделан для соблюдения уточнённого требования преподавателя. Для новых независимых проектов предпочтителен `NUMERIC_STD`; совместно пакеты в одном модуле не подключаются. [Документация GHDL](https://ghdl.github.io/ghdl/using/InvokingGHDL.html).

## Найденные дополнительные проблемы

- Questa-сценарий выполнял только первые 400 нс теста ядра. Теперь все тесты запускаются до самостоятельного завершения, с тайм-аутами и аварийным завершением при ошибках.
- Проверка длительности импульса в `struct_tb` ожидала завершения на один такт раньше. Исправлена; проверены длительности 1, 2, 3 и 8 тактов.
- В демонстрации кнопочный сброс снимался асинхронно. Теперь общий двухступенчатый синхронизатор снимает его по такту для обоих модулей.
- SDC задавал только частоту. Добавлены расчёт неопределённости такта и обоснованные исключения для асинхронной кнопки и светодиодов без внешнего такта приёмника. Внутренние пути не исключены из анализа.
- Начальные значения счётчиков генератора согласованы с асинхронным сбросом, что устранило критические предупреждения Quartus о Power-Up Level.
- Назначения контактов сверены с официальной схемой QMTECH V03; ток драйверов светодиодов явно задан как 4 мА для нагрузки через 1 кОм. [Схема производителя](https://github.com/ChinaQMTECH/CYCLONE_10_STARTER_KIT/blob/master/V3_10CL080YU484/Hardware/QMTECH-Cyclone10-Starter-Kit-V03.pdf).
- Обновлены описание, диаграмма состояний, временная диаграмма, PDF и копии исходников в приложении. Добавлена проверка совпадения копий.

## Неизменённые условия задания

Измерение фиксирует отсчёт перед первым спадом после центра, а не максимум за весь проход. Короткий ложный спад может завершить измерение. Если центр не обнаружен, автомат остаётся в измерении до обнаружения центра или сброса; тайм-аут и отдельное состояние ошибки не добавлены без требования задания. Конвейер постоянно разрешён: это учебная модель, без силовой части и аварийного останова. Для реального источника восьмиразрядного веса обёртке нужен согласованный интерфейс передачи данных; совпадение двух отсчётов само по себе не является полноценным CDC-протоколом.

## Перед сдачей

Протоколы моделирования и синтеза находятся в `verification/`. Необходимо физически прошить используемую плату, проверить D1/D2 и сброс, приложить подтверждение Programmer. Если преподаватель требует именно новые снимки RTL Viewer / Technology Map, их нужно экспортировать из актуальной базы Quartus: сохранённые снимки в отчёте помечены как исторические. Гарантировать принятие работы без текста исходного задания и проверки на плате нельзя.
