# FSM контроллера ONFI, вариант 3

Ядро разбирает запрос, проверяет его, управляет последовательностью фаз PHY и публикует ответ. [Контракт и архитектура](CONTRACT.md) описывают порты, поля, операции, ошибки и решения, которые нужно согласовать с соседними командами.

Для базового моделирования FSM и модель PHY используют один такт 125 МГц. Модель сохраняет слова, принятые на фазе WRITE, и возвращает их на READ по тому же адресу. Если аппаратный PHY получит отдельный такт, его сторона интерфейса подключается к ядру через адаптер между доменами. Для этого нужно согласовать передачу данных, команд, завершений и восстановления.

Актуальные требования находятся в [спецификации варианта 3](../specification/specification.typ). Сквозной сценарий запускается из [каталога интеграции](../integration/README.md).

## Запуск

Из каталога модуля в PowerShell:

```powershell
.\verify.ps1 -Check Simulation
.\verify.ps1 -Check Quartus
```

Для симуляции `vlib`, `vcom` и `vsim` должны быть доступны в PATH. Путь Quartus задаётся через `-QuartusBin`. Скрипт печатает каталог журналов. ModelSim сохраняет `regression.log`, Quartus сохраняет `onfi_fsm_check.fit.summary` и `onfi_fsm_check.sta.summary`. ModelSim Starter 2020.1 проверялся в каталоге с латинским путём, для этого по умолчанию используется профиль Public. Можно задать другой существующий каталог через `-BuildRoot`.

## Что проверяет модель

| Группа | Что сравнивается |
|---|---|
| READ на 9 байтов с адреса 3 | Фазы, адрес, отложенный done в WAIT_READY, разрыв между словами, данные, обнуление старших байтов хвоста, стабильность при остановке второго слова и заголовка |
| WRITE на 9 байтов | PHY остаётся неактивен до загрузки тела. Маска 0Fh превращает ABh в FBh. Статус C1h даёт NAND_FAIL и сохраняется как NAND_STATUS |
| Неверные запросы | Ранний и поздний EOP в метаданных адаптера, неверный empty, выход за страницу, LEN 513, неизвестный OPCODE, reserved, пересечение сегментов, Features без подтверждения. Передач команд PHY нет |
| Остальные операции | READ ID, READ PARAMETER с испорченной CRC первой копии, ERASE, READ STATUS, смена колонок и переупаковка двух сегментов, GET/SET FEATURES с чтением обратно, RESET после смены режима |
| WRITE → READ на 100 байтов | Модель сохраняет реально принятые слова WRITE. READ с того же адреса возвращает все 100 исходных байтов в 13 словах, с четырьмя нулевыми старшими байтами в хвосте |
| Максимальная длина | 512 байтов, 64 слова, полный проход адреса буфера в тестовом профиле |
| Ошибки и восстановление | Неверный last, лишнее слово PHY, преждевременный done, ошибка после частичного чтения, тайм-аут, reset при активной фазе, отсутствующий ack и блокировка FAULT |

Тесты сравнивают поля на передачах, а отдельный монитор следит за стабильностью при остановке команды, записи, слова ответа и дескриптора. Модель имитирует полный FIFO остановкой `ready` и пустой FIFO отсутствием `valid`. Она не реализует реальный CDC и электрическую шину. Внешние SOP/EOP/empty на выходе относятся к Master. Модель проверяет данные и длину, по которой Master рассчитает эти признаки.

В итоговом запуске ModelSim Starter 2020.1 скомпилировал три файла VHDL-2008 и выполнил все семь групп сценариев до 45,333 мкс. Компиляция и симуляция завершились с 0 ошибок и 0 предупреждений. Для проверки CRC эталон `CD42h` в модели рассчитан независимо от функции RTL.

## Quartus и TimeQuest

Quartus Prime Lite 20.1.1 прошёл Analysis & Synthesis и Fitter для `10CL025YU256C8G`. Использовано 1 311 логических элементов, 703 регистра и один M9K на 4 096 бит. В изолированной сборке порты виртуальные. Многочисленные предупреждения синтеза связаны с нулевыми/зарезервированными битами и применением общего назначения виртуальных выводов к внутренним узлам, для которых Quartus его игнорирует. Fitter сообщил два предупреждения о LogicLock и проигнорированных назначениях.

TimeQuest при периоде 8 нс прошёл по всем трём моделям задержек ядра. Худший setup slack **+0,125 нс** при медленной модели 85 °C, худший hold slack **+0,178 нс** при быстрой модели 0 °C. Проверочный скрипт завершает проверку ошибкой при отрицательном запасе. Измерены внутренние пути ядра. На интегрированном контроллере потребуются новый Fitter/TimeQuest, ограничения межблочных путей и физической шины, CDC-проверка FIFO и испытание с выбранной NAND или логическим анализатором.

## Инженерное ревью

| Наблюдение | Сценарий и исправление |
|---|---|
| Разный формат входа/выхода в вариантах 3 и 4 | Ответ READ9 при неверной разметке даёт другой opcode и длину. Ядро использует проектный формат младшими полями вперёд. Договор обязателен и у Master. Упаковка ответа в [onfi_protocol_fsm.vhd:129](onfi_protocol_fsm.vhd#L129) |
| Первоначальный такт не прошёл setup | При 8 нс TimeQuest показал −3,874 нс с заголовка к регистру адреса. Последующие разбиения сократили нарушение до −0,436 нс и −0,212 нс. В текущем RTL декодирование, проверка, выдача решения и проверка двух сегментов разнесены по тактам. См. [onfi_protocol_fsm.vhd:232](onfi_protocol_fsm.vhd#L232) и [onfi_protocol_fsm.vhd:360](onfi_protocol_fsm.vhd#L360) |
| Несоблюдение потока PHY | Ранний успешный done, неверный last и лишнее слово переводят ядро в RECOVER. Тест вводит каждое нарушение. См. [onfi_protocol_fsm.vhd:204](onfi_protocol_fsm.vhd#L204) |
| Переполнение колонки и длины | Ширина суммы 17 бит. Число слов вычисляется после расширения длины до 11 бит. Тест проверяет 512, 513 и пересечение страницы. См. [onfi_protocol_fsm.vhd:232](onfi_protocol_fsm.vhd#L232) |
| Повторное чтение старых данных после reset | RAM без очистки для вывода блочной памяти. После сброса действительность определяется состоянием и фактическим размером нового ответа. Проверяется новый READ STATUS после сброса текущего READ |

RTL содержит один синхронный процесс памяти, один процесс управления и полные комбинационные присваивания выходам. Запросы и статусы захватываются один раз по handshake. Проверены границы счётчиков потока и таймеров. Абсолютное ожидание входных и выходных FIFO намеренно определяется договором с адаптером. При backpressure эти состояния ждут передачи. Для завершения фазы PHY и восстановления есть независимые таймеры. Критерии проверки CDC, выводов, реальной NAND и timing полного контроллера описаны в [контракте](CONTRACT.md).

## Короткая защита

> Наша FSM принимает запрос с уже проверенными границами кадра, дополнительно проверяет аргументы, затем превращает opcode из пакета в последовательность фаз PHY. На READ на 9 байтов с адреса 3 мы передаём 00h, адрес страницы с колонкой 3, 30h, ожидание готовности и READ на 9 байтов. PHY возвращает два слова. Только после успешного done публикуем результат. Тело передаётся раньше дескриптора, чтобы буферизация могла открыть целый ответ. При WRITE ядро сначала принимает и проверяет всё тело, поэтому дефектный запрос не запускает программирование. Отдельный статус сообщает ошибку протокола или NAND. Синхронный буфер и разделение фаз проверены симуляцией и синтезом.

- **Почему `cmd_ready` и `done` раздельны?** Первый подтверждает, что PHY принял параметры фазы. Второй сообщает итог выполнения.
- **Почему в READ нет тела при LENGTH = 9?** В запросе это объём чтения. У ответа два 64-битных слова тела, на последнем Master поставит `empty=7`.
- **Почему надо сначала загрузить WRITE?** После 10h NAND могла начать программу. Проверить пакет и адрес нужно до выдачи команды.
- **Где обрабатывается асинхронность?** FSM и логическая сторона PHY в одном домене. Входной и выходной CDC относятся к FIFO, а физический R/B и задержки относятся к PHY.
- **Что даёт режим FAULT?** Секвенсор прекращает обмен, если PHY не подтвердил согласованное восстановление. Общий сброс очищает ядро и соседние очереди.
- **Что подтверждает TimeQuest?** В этой сборке измеряются внутренние пути ядра на целевой ПЛИС. Для итоговой проверки нужны настоящие верхний уровень, пины и задержки относительно соседних блоков.
