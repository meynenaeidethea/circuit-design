# Проверочная сборка контроллера ONFI

Входной Avalon-ST принимает пакет на 50 МГц. Двухтактовый FIFO передаёт слова в домен 125 МГц. Адаптер проверяет границы кадра, хранит тело и выдаёт дескриптор существующей FSM. После работы через PHY FSM выдаёт тело результата, затем дескриптор. Адаптер собирает внешний пакет и через второй FIFO передаёт его выходному регистру Avalon-ST на 50 МГц.

```text
Avalon-ST sink → DCFIFO → пакетный адаптер → FSM ↔ PHY → NAND
Avalon-ST source ← выходной регистр ← DCFIFO ← пакетный адаптер ← FSM
```

Это проверочный верхний уровень с синтезируемым трактом Avalon-ST. Модули соседних команд можно подключать после согласования интерфейсов. В тесте PHY заменён моделью, которая выставляет CE#, WE#, RE#, CLE, ALE, управляет DQ и ждёт R/B#. Содержимое NAND хранит Verilog-модель Macronix MX30LF1G18AC из групповой выгрузки.

## Граница проверки

Проверочная сборка использует собственный адаптер Avalon-ST, два потоковых FIFO Intel и модель PHY. [Спецификация варианта 3](../specification/specification.typ) предусматривает независимые очереди READ и WRITE и побайтные каналы PHY. Для проверки именно этой архитектуры нужны командные модули или согласованные адаптеры.

125 МГц для Logic подтверждены в чате. На доске отдельно подписаны `Clk_L` и `Clk_O`. Поэтому 125 МГц на портах PHY в этой сборке задают сторону интерфейса FSM.

### Подключение PHY с собственным тактом

Адаптер на стороне 125 МГц должен видеть одну активную фазу. Для передачи между доменами использовать двухтактовые FIFO для фаз, слов записи, слов чтения и завершений. Помечать записи идентификатором фазы, включая поколение обмена. В домене PHY открывать фазу после принятия её описания. В домене FSM выдавать успешный done только после принятия последнего слова чтения, даже если очередь завершений стала видна раньше очереди данных.

При восстановлении остановить новые передачи. Отдельный синхронизированный запрос восстановления должен работать даже при заполненной очереди. Очистить обе стороны очередей и подтвердить готовность только после остановки старой фазы, согласованного снятия сброса и готовности PHY. Новое поколение обмена открывать после снятия запроса и подтверждения. Проверить разный порядок видимости данных и done, позднее завершение прежней фазы и reset при заполненных очередях. Реализация этого адаптера зависит от подтверждённых портов и тактов В5/В6.

## Команды запуска

Запусти команды в PowerShell из каталога `task2`.

```powershell
.\fsm-control\verify.ps1 -Check Simulation
.\integration\verify_integration.ps1 -Check Simulation
.\integration\verify_integration.ps1 -Check Quartus
```

Для сквозной симуляции нужен исходный ZIP с моделью MX30LF1G18AC. Передай путь через `-ChatArchive <путь к ZIP>`, если архив лежит вне каталога загрузок Telegram. Скрипт извлекает единственный исходник модели Verilog во временный каталог и печатает путь к журналам. Результаты сохраняются в `integration.log`, `onfi_integration_check.fit.summary` и `onfi_integration_check.sta.summary`. ModelSim должен видеть `vlib`, `vlog`, `vcom` и `vsim` в PATH. Для Quartus можно передать `-QuartusBin`. Синтез использует RTL FSM, адаптер, два DCFIFO и верхний уровень. Модели PHY и NAND участвуют в симуляции.

## Что проверяет сквозной сценарий

- Хост передаёт WRITE и READ подряд по входному Avalon-ST. Адрес в обоих пакетах равен 2051, то есть страница 1 и колонка 3. Данные программируются в модели NAND и читаются из неё через физические сигналы модели.
- Сравниваются статусы, ID, все 100 байтов, 13 слов тела, последний `EOP` и `empty=4`. Остановка `ready` проверяет стабильность выхода, последовательное сравнение и проверка пустого выхода ловят потери и дубли.
- В запросе 09h с намеренно неверным первым сегментом входной буфер принимает 65 слов тела и освобождает их без обращения к PHY. Отдельные кадры проверяют восстановление по новому SOP и неверный `empty`.
- Общий сброс очищает уже готовый, заблокированный ответ и неполный запрос. После запуска новый READ возвращает сохранённые 100 байтов. Этот сценарий сбрасывает контроллер после завершения физической фазы NAND.

У MX30LF1G18AC асинхронный интерфейс ONFI 1.0. Модель отпускает открытый сток R/B# при готовности, поэтому тест добавляет слабую подтяжку к единице. После записи модель возвращает статус E0h. Тест проверяет сохранение этого байта в NAND_STATUS.

## Проверка FPGA

Quartus Prime Lite 20.1.1 выполнил Analysis & Synthesis, Fitter и TimeQuest проверочного верхнего уровня для Cyclone 10 LP `10CL025YU256C8G`. Использовано 1 954 логических элемента, 1 095 регистров и 9 блоков M9K, 30 016 бит памяти. Худшие запасы для `logic_clk` (125 МГц) равны +0,134 нс setup и +0,156 нс hold. Для `avalon_clk` (50 МГц) они равны +14,744 и +0,164 нс. Recovery и removal также положительны. Первый прогон показал −1,566 нс по setup на пути от буфера запроса к FSM и отрицательный запас от ответного буфера к FIFO. Добавлены регистры после двух буферов, а тактовые порты выведены из списка виртуальных выводов.

Оба такта в SDC объявлены и независимы. Между ними проходят два DCFIFO Intel с синхронизацией указателей. Снятие сброса синхронизируется в каждом домене, до этого обмен заблокирован. TimeQuest обнаружил 57 цепочек синхронизации, для части цепочек расчёт MTBF отсутствует. Это проверка зарегистрированных внутренних путей и структуры двух пересечений Avalon-ST ↔ Logic. Все порты данных в этой сборке виртуальные, у двух тактов и сброса автоматические назначения выводов. Внешние задержки, физическое подключение и отдельный домен PHY предстоит проверить после выбора платы и получения реальных модулей. · [Руководство Intel по DCFIFO](https://www.intel.com/programmable/technical-pdfs/683522.pdf)
